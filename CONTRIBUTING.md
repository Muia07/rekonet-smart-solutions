# Contributing to Rekonet Systems Website

Thank you for your interest in contributing to the Rekonet Systems website! This document provides guidelines and information for contributors.

## 🤝 How to Contribute

### Reporting Bugs
1. Check existing issues to avoid duplicates
2. Use the bug report template
3. Provide detailed reproduction steps
4. Include screenshots if applicable

### Suggesting Features
1. Check existing feature requests
2. Use the feature request template
3. Explain the problem you're solving
4. Describe your proposed solution

### Code Contributions
1. Fork the repository
2. Create a feature branch
3. Make your changes
4. Test thoroughly
5. Submit a pull request

## 🛠️ Development Setup

### Prerequisites
- Git
- Node.js 14+ (optional)
- Modern web browser

### Local Development
```bash
# Clone your fork
git clone https://github.com/yourusername/rekonet-systems.git

# Navigate to project
cd rekonet-systems

# Start development server
npm start
# or
python -m http.server 3000
```

### Project Structure
```
rekonet-systems/
├── index.html              # Main website
├── package.json            # Project config
├── public/                 # Public assets
├── src/                    # Source files
│   ├── css/               # Stylesheets
│   └── js/                # JavaScript
└── docs/                   # Documentation
```

## 📝 Code Standards

### HTML
- Use semantic HTML5 elements
- Include proper accessibility attributes
- Maintain consistent indentation (2 spaces)
- Add comments for complex sections

### CSS
- Follow BEM naming convention
- Use CSS custom properties for theming
- Mobile-first responsive design
- Optimize for performance

### JavaScript
- Use ES6+ features
- Write clean, readable code
- Add comments for complex logic
- Handle errors gracefully

## 🧪 Testing

### Manual Testing
- Test on multiple browsers (Chrome, Firefox, Safari, Edge)
- Test on different devices (desktop, tablet, mobile)
- Validate HTML and CSS
- Check accessibility with WAVE tool

### Performance Testing
- Run Lighthouse audit
- Check Core Web Vitals
- Test loading speed
- Validate structured data

## 📋 Pull Request Process

### Before Submitting
1. Update documentation if needed
2. Test all changes thoroughly
3. Ensure code follows standards
4. Update CHANGELOG.md if applicable

### PR Description
- Describe what changes were made
- Explain why changes were made
- Reference related issues
- Include screenshots for UI changes

### Review Process
- Maintainers will review your PR
- Address any feedback
- Make requested changes
- PR will be merged when approved
